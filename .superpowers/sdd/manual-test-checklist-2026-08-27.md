## 一、桌面 UI（第一波改动，5 项）

### ☐ 1. 折叠态聊天
- 步骤：收起左侧栏 → 展开；收起输出面板 → 展开；反复几次。
- 预期：布局不抖动、不错位；聊天内容与滚动位置不丢；再次展开宽度合理。

### ☐ 2. 抽屉开合与跟随
- 步骤：打开左抽屉、右抽屉；开着抽屉拖动主窗到新位置；最小化主窗 → 任务栏恢复。
- 预期：抽屉跟随主窗移动，不脱节、不漂移；最小化恢复后抽屉相对主窗位置正确，开合状态正确。

### ☐ 3. 防跳底
- 步骤：让 agent 跑一个长输出任务（输出持续刷屏）；中途向上滚动阅读历史。
- 预期：向上滚动后，新内容到达时视图**不被拽到底部**；手动滑回底部后恢复跟随新输出。

### ☐ 4. Z-order（摘 HWND_TOPMOST 后，多显示器重点）
- 步骤：打开抽屉 → 切到别的应用（浏览器/终端）→ 再切回；把主窗拖到第二台显示器重复一遍；再试试别的应用全屏时主窗+抽屉的层级。
- 预期：抽屉**不再压**在别的应用窗口上；切回时主窗与抽屉层级关系正常（抽屉仍依附主窗，不掉到主窗后面）。

### ☐ 5. provider 编辑不抹 key（I1 回归）
- 步骤：设置 → provider 页 → 编辑一个**已存有 key 的** provider（改名称或 base_url，不动 key 字段）→ 保存 → 重新打开编辑页确认；再用它发一条消息确认可用；最后故意填一个非法值触发一次报错。
- 预期：保存后 key 不被抹空（重新打开时 key 位显示已保存状态）；该 provider 仍能正常对话；报错文案准确指向问题字段，不是泛泛/错误提示。

## 二、进程行为（W2 改动，2 项）

验证辅助命令（PowerShell，可随时跑）：
```powershell
# 看 node/cmd/flashgrep 进程及其父进程
Get-CimInstance Win32_Process -Filter "Name='node.exe' or Name='cmd.exe' or Name='flashgrep.exe'" |
  Select-Object ProcessId, ParentProcessId, Name, CommandLine | Format-List
```

### ☐ 6. 开关 MCP/LSP 无孤儿进程
- 步骤：记录基线（先跑上面命令看一眼）；设置里反复开关 MCP server / LSP 数次（每次间隔几秒）。
- 预期：关掉之后对应的 node/cmd/flashgrep 进程随之退出；任务管理器里没有"父进程已不存在"的残留孤儿。

### ☐ 7. 关应用无残留
- 步骤：正常退出应用（关主窗）→ 等 5 秒 → 跑上面命令 + `Get-Process flashgrep -ErrorAction SilentlyContinue`。
- 预期：无 flashgrep.exe、无本应用拉起的 MCP 子进程残留。

## 三、provider 编辑（W7/F7 新增，1 项）

### ☐ 8. 设置页编辑 provider 全流
- 步骤：设置 → 接入点 → 任一行点「编辑」→ 改个名称保存（列表应刷新显示新名）→ 再打开编辑，API Key **留空**直接保存 → 用该 provider 发一条消息（验证 key 没丢）；再试「测试连接」按钮（应出结果）；最后试着删除当前默认的 provider（应被拒绝并提示先切换默认）。
- 预期：编辑保存生效、留空 key 不丢、测试连接有明确成败提示、默认 provider 拒删。

### ☐ 9. 重启持久化（验收环"第二天还记得"）
- 步骤：随便聊几句 → 完全关掉应用 → 重新打开。
- 预期：会话和消息原样还在（用户 2026-08-29 澄清：此项 = 单 session 缓存不消失）。

### ☐ 10. 确认门三档（W9-1）
- 步骤：让它执行一个需要确认的操作（如跑 shell 命令）→ 审批卡出现三个按钮（批准/拒绝/本会话内允许 <工具名>）→ 点「本会话内允许」→ 再让它执行同类操作。
- 预期：首次弹卡三按钮齐全；选了会话允许后，同类操作不再弹卡、但记录里能看到"已自动允许（本会话）"；重启应用后允许失效（再弹卡）。
