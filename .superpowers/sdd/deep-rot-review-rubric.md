# 代码层腐化深审量规（god-file 活体对照实验专用，2026-08-28）

> 用途：对 rot-budget.json 登记的 8 个超线观测样本做**代码层**腐化审查。结构层结论（行数/走势/职责）已有 `rot-probe-2026-08-28.md`，本审只看代码本体。你是怀疑论者：默认有腐化，用证据说话；干净也要给证据（抽查了什么）。

## 审查清单（8 项逐项过，每项给：发现数 + 代表案例 file:line + 分级）

1. **死代码**：unreachable 分支、注释掉的代码块、遗留 cfg 门、从未被调用的私有 fn（codegraph/rg 双确认引用为零才算）。
2. **重复**：文件内 >5 行的复制粘贴块；与仓内其它文件的逻辑重复（codegraph 抽查 2-3 个可疑点）。
3. **模式不一致**：错误处理风格混用（unwrap/expect/?/let _ 同文件无规律混用）、命名风格漂移、同类问题两种解法并存。
4. **注释腐化**：与实现不符的注释/doc、过期 TODO/FIXME/HACK（用 git blame 或 git log -S 抽样定年齢）、被删功能的墓碑注释。
5. **hack/绕路**：无注释的 workaround、魔数、可疑 sleep/retry/polling、为过编译器的怪写法（无 ponytail 注释标注的）。
6. **职责归属错误**：明显不属于本文件职责的逻辑（给具体案例；参照该文件所在模块的 AGENTS.md/邻近模块划分）。
7. **复杂度热点**：>80 行函数清单、嵌套 >4 层的块、参数 >6 个的函数、单 match 超 20 臂。
8. **测试质量**（若有内联测试）：真断言 vs 恒真/走过场；覆盖的是关键路径还是边角；测试与生产代码是否纠缠。

## 分级

- **腐化证据**：实质性的、会随时间恶化的（死代码堆积、复制块、注释与实现矛盾）
- **观察项**：存在但稳定/有界
- **干净**：抽查了但没发现（写明抽查方法）

## 总判定（每文件）

`腐化中 / 稳定 / 健康` + 与结构层初判（rot-probe 报告）**一致还是推翻** + 一句话理由。
推翻结构层判定是允许的、有价值的——结构信号可能误判（大文件可以代码层很干净）。

## 纪律

- 只读：不改代码、不 commit、不跑 cargo（除只读 grep/codegraph/git log）。
- 一切发现带 file:line 证据；禁止凭文件名/行数推断（结构层已犯过的错：把 diff 偏移当行数）。
- 不确定的进"无法判定"清单，禁止猜。
