# NortHing 产品论题（Product Thesis）

> 状态：**v1.4（2026-08-17 修订）**。v1.0（2026-08-16）拍板主论题 A + 小圈起步；v1.1 同日 grill 定稿 14 项决议（G1-G14）；v1.2 采纳 G15 演化自评审并修正 judge_gate 处置；v1.3 拍板 **MiniApp 子系统整删** + **插件连接系统（PCS）0.3 末启动**（core-agent 最优先）；v1.4 拍板 **PCS 权限批准者=用户安装时批准**、**遥测边界（v1 数据不离机，本地统计不算遥测）**、**验收环第六步（用 PCS 装一个插件看它用起来）**。本版为当前单一事实源。决策人：用户。
> 核心立场（grill 确立的产品签名）：**agent 自主最大化 + 产品面最小化**——记忆归 agent 所有、身份演化完全自主、交互半被动、无移动通道、降级即报错。

---

## 1. 一句话论题

**NortHing 是你的个人 AI 同事：一个有身份、有记忆、会成长的单一 agent，住在你的桌面；coding 是它的职业技能，不是它的身份。**

## 2. 产品原则（按此裁决后续所有设计争议）

1. **关系连续性是产品本身。** 会话跨升级无损、记忆完整、身份可追溯，优先级高于任何单项功能。
2. **单一主 agent。** 产品围绕"你的那位同事"构建；subagent 是它的工作方式，不是产品面。跨 workspace 也是同一个自我（workspace 只是它的工作台，G9）。
3. **coding 是职业技能包。** 工具面持续建设，但不派生独立产品面（CLI 永久 frozen，除非 agent 自己需要它，G13）。
4. **记忆是 agent 的自主资产（G2）。** 用户**可阅读**（透明面板），**不可更改、不可删除**——没有编辑/遗忘按钮；记忆的增删改（含遗忘）全部由 agent 自己决定，用户只能通过对话影响它。
5. **身份演化完全自主，自评审前置（G3 + G15-b）。** 演化与否、何时演化，由 agent 自己判断；不设**用户**回滚、不限速、无冷静期。判断过程包含**自评审**：变更执行前 agent 派子代理分身评审自己（证据：工具轨迹/文件 diff/统计样本），裁决通过才落地。一切演化**必须留审计**（裁决理由 + 旧→新 + 触发原因），且 P2-12 防自我验证闭环（agent 不读 episodes 做决策）升为硬门禁——**自评审的证据同样禁取 episodes**。
6. **半被动交互（G1）。** cron 类定时任务可用（如每晚摘要），但 agent 不主动发起联系——LLM 架构上不存在人类式的灵机一动，产品不假装有。
7. **确认门默认开启。** 同事语义下，用户对"它做了什么"的可见性高于效率。
8. **无移动通道（G4）。** remote/mobile 栈整体删除；未来如需移动，基于 T5 协议以客户端形态重写，不复用旧栈。
9. **降级即报错（G8）。** key 耗尽/quota 用完：直接提示错误信息。不做 failover 链（人格漂移与身份稳定冲突）、不做休眠模式、不做本地应急脑。

## 3. 成功度量

> 采集方式（2026-08-17 拍板）：本地统计，数据不离机；遥测 = 离机回传，小圈期零遥测。

| 维度 | 指标 |
|---|---|
| 关系连续性 | 升级/重启后 会话+记忆+身份 无损恢复率（T5 验收直接引用） |
| 记忆质量 | 对话纠正频率（用户在对话中纠正它记错的事，越低越好）——纠正是唯一影响通道（原则 4） |
| 身份可追溯 | 演化审计覆盖率 = 100%（有变更必有裁决 + 审计；无审计的漂移 = 事故）；裁决记录完整率（含证据摘要与理由） |
| 职业能力 | 工具调用成功率 |
| 降级诚实度 | key 耗尽时错误信息清晰度（不静默、不降智冒充） |

## 4. 已接受的显式风险（用户知情拍板，防未来 session 重新翻案）

| 风险 | 拍板 |
|---|---|
| 它记错了关于你的事，你无法直接改/删，只能对话纠正且由它决定 | 接受（G2） |
| 一次坏演化不可回滚，可能影响积累数月的人格与记忆 | 接受（G3） |
| 小圈期记忆/身份明文落盘、无加密 | 接受；**公开发布前必须重估本表全部三条**（G14 门槛清单首项） |

## 5. 被否决的备选（含翻转记录）

- **移动通道**：翻转两次——v1.0 拍板"保留 remote"，grill 中改"先不做"，最终定**直接删栈**（既然不做，留着是攻击面+维护债）。将来走 T5 协议客户端重写。
- **记忆面板可编辑/资产级控制（导出擦除回滚）**：否决——与"记忆归 agent"哲学冲突。
- **failover 链 / 本地应急脑**：否决——不同模型的"它"味道不同，failover 等于人格漂移；报错更诚实。
- **演化用户护栏（快照回滚/限速冷静期）**：否决——用户护栏即用户干预。注意与 G15-b 区分：**自评审不是用户护栏**（评审者是 agent 自己的分身），v1.2 采纳。
- **judge_gate 全删**：v1.1 曾拍"不复活仅参考"；v1.2 修正为**分边处置**——agent-runtime 协议层（verdict/evidence/redline/receipt 词汇，1,473L 纯类型）保留为 TH-2/TH-5 起点，assembly/core 适配层（1,690L，未接线）删除。
- **B「开发者工作台」/ C「Agent 容器」**：维持 v1.0 裁决（B 吸收为技能包；C 留 2.0，协议为其留口）。C 的形态修订（v1.3）：第三方以 **MCP/ACP 协议插件**扩展同事能力，不再基于 MiniApp。
- **MiniApp 子系统（内置四件套 + 宿主，~6k 行）**：2026-08-17 拍板**整删**——MiniApp 是"壳的功能"而非"同事的本体"，与 core-agent 最优先冲突；`permission_policy` 的默认拒绝语义在删除前提炼，作为 PCS 权限框架重生。

## 7. 1.0 验收环（六步，纯桌面）

**安装 → 创建身份（四字段+五色板）→ 对话 → 它记住了 → 第二天回来它还记得 → 用 PCS 给它装一个插件，看它用起来。**

此环全绿 = 1.0 候选。原第六步"手机上继续"已随移动通道删除（§5）；替代第六步（2026-08-17 拍板，P-17）同时验收 PCS 注册/面板/权限与"同事会长新技能"的产品故事。
